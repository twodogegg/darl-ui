# VideoCompare｜多视频同步对比（规划草案 v0.1）

状态：**仅规划，尚未开发**。所属仓库：`darl-ui`。组件名：`VideoCompare`。

## 1. 为什么要做

用户可能针对同一镜头生成多个 AI 视频版本。逐个播放很难比较人物一致性、动作、嘴型、镜头稳定性、画质等细节。希望把这些版本放在同一页面统一播放，且只能听一个指定版本的声音。

此组件只负责前端比较；不生产视频、不负责上传存储，也不要求业务项目使用特定素材平台。

## 2. 第一版范围

- 同时显示 **2–4 个**视频；默认 2 个，3–4 个采用 2×2 网格；布局随容器响应式调整。
- 每格展示版本名、视频画面、加载/错误状态和当前声音标识；可删除/替换版本（由宿主控制数据）。
- 视频画面按原比例 `object-fit: contain` 完整显示；禁止默认裁剪和扭曲，支持横版和竖版混用。
- 一个公用播放控制栏：播放/暂停、跳转、时间/总时长、重新开始、全局循环、统一播放速度（0.5× / 1× / 1.5× / 2×）。
- 使用**一条全局时间轴**，所有视频从各自 0 秒一起运行。拖动进度条对所有视频生效。
- 声音选择：**无声音 / 视频 A / 视频 B / 视频 C / 视频 D**（仅对当前存在的项显示）。默认第一个视频；保证同一时刻最多一路音频未静音。音源切换时不重置进度、不重新开始，上一音源立即静音。
- 不同视频时长：默认全局总时长 = 最长视频时长；较短视频结束后保持最后一帧，不单独循环；若被选为音源的短视频提前结束，后续自动静音直至全局时间轴结束。
- 播放中某视频加载失败时展示错误状态，其余视频可以继续查看；开始时未读取到有效视频元数据应阻止“全部已同步”的误导性状态。
- 兼容鼠标与触摸操作，键盘焦点可见，控件带必要无障碍标签。
- 演示站提供本地选择多个文件进行真实对比；本地文件不上传到服务器，同时提供示例说明组件 API。

## 3. 建议的界面结构

```text
视频对比                            3/4 个视频  [添加视频]
┌─────────────────────────┬─────────────────────────┐
│ A / 版本 01       🔊     │ B / 版本 02             │
│                         │                         │
│      VIDEO A            │       VIDEO B           │
│                         │                         │
├─────────────────────────┼─────────────────────────┤
│ C / 版本 03              │  + 添加第 4 个视频        │
│                         │                         │
│      VIDEO C            │                         │
│                         │                         │
└─────────────────────────┴─────────────────────────┘
[播放/暂停] [00:04 ━━━●━━━━━━ 00:15] [循环] [1.0×]
声音来源：[版本 01 ▾]  /  [全部静音]
```

- 视频卡片上的“声音”只标记当前选定音源；避免每张视频各自拥有独立播放/静音控件，造成不同步和声音混合。
- 非音源视频保持静音但仍解码显示；选择音源时只更新声音，不替换视频元素。
- 视频内容保持原始帧，不叠加字幕、水印和装饰性文字；卡片名称属于播放器 UI，不烧录到视频。

## 4. 同步播放实现边界

浏览器多个 `<video>` 分别调用 `play()` 并不能保证逐帧同步。

v0.1 采用**统一播放控制器**：
1. 加载各视频 metadata，保存有效时长，建立全局时间轴；
2. 用户触发播放时协调各视频启动，并正确处理 `play()` Promise 拒绝（浏览器策略、格式不支持等）；
3. 通过共同的目标时间位置控制视频 `currentTime` 和相同的 `playbackRate`，超出容差时纠偏而不是每帧都强行 seek；具体容差在实现和实际浏览器测试中校准；
4. 拖动进度、暂停、重新播放、改变速度、修改输入列表均重设/协调统一状态；
5. 使用 `requestVideoFrameCallback` 能力时做特性检测，提供回退路径；浏览器后台标签页恢复后重新对齐；
6. 不承诺专业后期软件意义上的逐帧锁定精度；需要用实际帧率、不同编码文件验证可接受的同步误差。

如果容差导致频繁跳帧，应减少纠偏频率并显示“同步中”状态；不要用暴力高频设置 currentTime。

## 5. 推荐公开 API（草案）

```tsx
export interface CompareVideo {
  id: string;
  name: string;
  src: string;       // http(s) URL 或由业务侧创建的 blob URL
  poster?: string;
}

export interface VideoCompareProps {
  videos: CompareVideo[];             // 2–4 个
  audioSourceId?: string | null;     // null = 全部静音
  defaultAudioSourceId?: string | null;
  onAudioSourceChange?: (id: string | null) => void;
  onRemove?: (id: string) => void;
  onError?: (id: string, error: Error) => void;
  loop?: boolean;
  accentColor?: string;
  className?: string;
}
```

- `videos` 与媒体来源由业务调用方提供；组件不自行发起上传、生成签名 URL、刷新 CDN 凭据或保存对比会话。
- 支持受控的 `audioSourceId` 以及非受控的 `defaultAudioSourceId`；父组件修改选择后播放器应保持共同时间轴。
- `src` 首版统一用 URL 字符串，File/Blob 的 `URL.createObjectURL` 与撤销由创建方负责；演示站自行管理本地文件 URL 生命周期。
- 只有在真实开发需求出现时才扩充事件/配置字段，不提前设计通用媒体编辑数据模型。
- 入库、版本选择、视频链接过期后的刷新由宿主项目负责。

## 6. 必须测试的场景

1. 两个等长视频同步播放，拖动进度后恢复同步。
2. 3 个和 4 个视频同时播放，卡片不变形；横竖版混合时比例正确。
3. 切换视频 A/B/无声音：确保任意时刻最多一个未静音，时间位置不跳变。
4. 10s 与 15s 视频对比：前者 10s 时冻结末帧，时间轴继续至 15s；选前者为音源时后 5s 无声。
5. 改变播放速度和全局循环，全部视频共享行为。
6. 加载很慢、格式不支持、资源 404、`play()` 被拒绝时有明确反馈，不出现错误的成功播放状态。
7. 删除正在播放/发声的版本时，自动选择其他有效音源或全部静音，定时器/监听器正确清理。
8. 浏览器标签页后台再恢复、暂停后恢复以及移动端媒体限制下的行为。
9. 本地 blob URL 与远程 URL 均能播放；演示站不会上传文件、也不会泄露签名 URL 到持久化日志。

## 7. 暂时不做（保持最小可用）

- 时间轴逐视频偏移和逐帧对齐、A/B 擦除滑块、叠加半透明、差异热力图。
- 多声道混音、导出对比视频、拼接/转码/压制。
- 服务端视频上传、云端同步、对比历史、评分数据库、多人协同。
- 超过四个视频的同时解码、自动音量响度均衡和独立拖动每张视频进度。
- 截帧导出、视频缩放放大、帧级标注，待第一版使用后按需要决定。

## 8. 分阶段开发建议

1. UI / 数据接口：卡片与响应式网格，来源列表、加载/错误状态，演示站本地文件。
2. 共用控制器：加载元数据、公共播放/暂停/seek/speed/loop、时长不同的处理。
3. 音频选择：单音源不变量、运行时切换、失效音源的回退。
4. 稳定性：同步纠偏、浏览器异常处理、清理资源及针对关键边界的测试。
5. Playground：支持不同尺寸、时长的试验文件；文档、API 示例。

## 9. 待用户确认的产品选择

- **对比数量**：建议第一版 2–4 个，未来有明确需求再扩展。
- **不同时间长度**：建议按最长为准、短视频末帧停留。
- **是否需要单视频放大**：建议先不做；若用户最常用来对比人物脸部/嘴型，作为下一步优先功能。
- **是否需要手动错位对齐**：第一版默认全从 0 秒开始；只有真实案例确实存在起始偏差时，再加入独立偏移。
- **对比完成后怎么选最佳版本**：与业务相关；宿主可以包一层“选中最佳”操作，而 VideoCompare 本体不存储评分。
