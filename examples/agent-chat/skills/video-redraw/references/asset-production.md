# 拉片后的资产整理与制作

## 从当前状态继续

先发现工具并查询项目、资产、分镜、片段、转绘任务和已有媒体结果。按任务实际阶段继续：只有原片则 prepare/analyze；已有分析草稿则核对后 apply；已有资产则补字段和关联；已有合格目标图则直接进入分镜。调用前加载 darl-studio 并 describe 所需资源，不重复提取已有主体或重新付费生成成功素材。

`apply` 创建新资产时保存分析返回的目标字段；已有资产会受到保护而跳过，不会靠再次 apply 自动补齐。已有记录缺项时，用编辑工具按最新版本逐字段补充，保留人工设定、原片证据、图片历史和引用。写后回读验证，不能只回复一份清单。

## 提取什么、保存到哪里

逐镜检查人物、场景和参与动作的关键道具，跨镜头归并同一主体。床、窗、沙发等固定布景一般归场景；被拿取、交接、反复特写或推动剧情的物件才需要独立道具。道具为0不一定是遗漏，须对照原片核实。

| 字段 | 内容与边界 |
| --- | --- |
| name / type | 目标名称及角色/场景/道具类型；沿用真实主体 ID |
| description | 角色身份、关系及剧情作用；场景/道具用途。未知身份标待确认，不猜姓名、亲属关系 |
| appearance | 角色可见年龄感、脸型、发型发色、肤色、配饰；场景空间布局、光源和材质；道具形状、颜色、材质 |
| costume | 角色主形象服装版型、颜色、可见材质；没看到的下装、鞋子不当原片事实 |
| voiceDescription | 原声可确认的音色、语速、语气；没有声音依据留空或说明待确认，不据脸推音色 |
| prompt | 可执行的资产生图指令，说明主体、图像用途、背景/排版及必须保留的特征 |
| source | 原视频 fileId、真实 start/end/frames、原始名称/描述；不拿目标图覆盖证据 |
| variants | 原片确实存在的换装/状态差异；同人不同镜位不新建主体 |

分析草稿的 targetDescription/targetAppearance/targetCostume/targetVoiceDescription/targetPrompt 分别对应上述 description/appearance/costume/voiceDescription/prompt。旧草稿没有这些细分字段时，回读原片证据再补，不能把一句 description 机械复制到每个输入框。

目标地区用于语言和合理的场景适配。是否改变面容、服装以用户要求和当前已确认设定为准，不能因选择欧美就自动换掉所有人的族裔。先区分观察事实与新设计，保留来源关系。

## 资产图的具体做法

- **角色主图**：用于跨镜头识别同一个人。默认整理成中性背景的一致性图，脸、发型、服装保持同一主体。可用2×2版式呈现正面头肩、侧面头肩、正面服装和背面；只依据可确认的设定绘制，原片没有的信息注明待确认。原帧中即使人物躺着、被另一人抱着，也不要求主资产复刻躺姿、床铺、另一人的手臂。清晰面部图可作为补充，按实际需要生成。
- **场景主图**：无人空镜，保留出入口、家具相对位置、窗外环境、主要光源和可行动空间。原片只展示局部时保留未确认项，不宣称已还原完整房间；需要多角度时用同一空间的衍生图。
- **道具主图**：单独呈现原片中的同一件物体，保持关键形状、材质和功能。若道具已在可用场景/角色图中清晰可辨且不需单独复用，不强制多生成一张。
- **剧情分镜图**：人物入场景后的构图、站位和动作，保存到片段的 image/storyboardImage/blockingImage 等当前支持字段；不能把这种图当成角色主资产完成。

准备请求时列清实际参考顺序与用途。首次提取资产用该主体清晰原帧；已有确认目标形象时优先复用它。拼图用于拉片概览，生成人物主资产优先用对应单帧，不把多人拼图直接当单人脸参考。背景、旁人身体应在指令中明确移除，保留当前主体可识别特征；不是简单“保持原帧姿势和背景只换脸”。

原片截图直接填入 asset.image，只是选用了参考图片，不等于生成了合格的目标资产。历史任务即便 completed，也要查看结果是否符合当前资产用途。沿用用户已确认的图片；发现用途不符先说明并保留历史，未经当前任务授权不批量重做。

## 真正写入与生图

1. 查询 assets describe 和当前主体最新 _version，编辑 description、appearance、costume、voiceDescription、prompt、source 等缺项，回读确认字段。无法确认的项明确保留缺口。
2. 当前任务包含生图时，发现当前图片模型能力与参数，引用实际原帧或确认目标图。调用媒体生成工具时传 options.studioTarget={resource:"assets",id:真实资产ID,version:最新版本,field:"image"}；变装另传当前支持的 variantId。不得凭空编造任务ID。
3. 查询任务到成功/失败，查看实际图片。核对指定人物是否单独出现、面部服装是否一致、场景是否无人、道具是否对应原物。失败时保留已成功结果。版本冲突时回读目标；结果可能只进入历史，不假定主图自动选用成功。
4. 用查询工具验证 asset.image、history、variants 及 source，明确哪些资产已可供下游使用。source.confirmed 只在证据和目标设定确已核对后标记，不把任务完成当作人工确认。

## 从资产继续到分镜、视频、成片

资产整理后继续当前授权范围内的步骤，不停在抽帧或清单：

1. **分镜**：读取已保存 shots，保留原始 source，校对目标画面、对白说话者、assetIds 和场次。缺失主体先有证据再补；翻译保留原意。将目标时长与原片时间区分；用户要求保持原时长时先压缩译文表达，无法容纳时说明，不静默延长。
2. **片段**：用真实 episodeId/sceneId/shotIds 建立或更新 clips，同场镜头按顺序组合；duration 是对应目标时长之和，遵守当前模型时长上限。assetIds 汇总这些镜头需要的主体，勿按显示名关联。
3. **分镜图**：按需要将确认人物图、场景图、道具图合成镜头构图，保留姿态/动作与空间关系；结果关联片段图像字段。无需中间图的模型可直接使用已确认资产图，减少重复生成。
4. **视频**：按模型实际参考输入顺序编排提示词，逐镜写动作和目标语言对白。使用多模态参考，确认真实目标图已进入请求；当前H3入口已支持 referenceVideos 和 referenceAudios，可分别传选定原片片段及实际音频/音色试听地址，音频须搭配图片或视频；先核对当前模型能力、schema与参考用途。首尾帧仍未接通。不支持的能力如实说明，不偷换成无参考文生视频。
5. **验收导出**：查询视频任务、回读片段 videos/currentVideo，检查实际画面、目标语言音轨、对白完整度和镜头衔接。选择确认视频后用当前 export 操作按顺序合成，检查实际成片和下载。文字译文、已提交任务都不等于成片完成。

每次阶段交付说明已经保存/生成的实际记录、当前缺口和下一步；复用可用结果，不为演示流程重复生成。
