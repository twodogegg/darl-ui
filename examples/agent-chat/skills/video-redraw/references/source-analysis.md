# 原片分析与补漏

## 时间与证据

读取视频真实时长、画幅、帧率和音轨。按现有工具支持探测、抽帧或截取区间，不假设某个 CLI、转写服务已经安装或配置。

先概览完整视频，理解事件顺序、人物关系、重要动作、反应和关键道具；再逐镜检查。候选切镜点辅助定位，不等同于场次变化：同一场景的正反打仍可属于同一场次。

每个镜头检查开始、中段、结束附近的有效画面，必要时加密动作前后采样，避免只看首帧漏掉递物、入画或离场。连续运动需要连续片段证明，稀疏截图不能证明间隔内没有其他动作。

有对白时使用原语言转写，保留真实时间段并结合画面校对说话人。只有无时间戳文本时，不能伪造逐字或逐句对齐；可以将明确听到的内容关联到所选区间，注明对齐精度和不确定处。画外音与画面人物分开判断。无声/无对白片段跳过转写，仍分析动作。

对白、字幕和画面中文字是不同证据；不默认字幕完全等于实际语音。模糊文字和听不清的台词保留缺口。

## 批量抽帧与拼图

在网站内，先查询已有切镜和转写任务并复用结果。当前工具提供 `breakdown` 时用它取得镜头和带时间映射的拼图；否则用 `prepare` 取得来源镜头及参考帧。有声原片按需用 `transcribe` 获取真实原语言转写。助手直接读取拼图或单帧并分析，按授权使用工作台工具保存结果。

只有需要离线分析或工具未提供抽帧时，才直接运行随包的 `scripts/video-frames.mjs`。需 Node.js、PATH 中的 `ffmpeg`，以及当前工作目录能够解析的 `sharp` 包；本网站工程已有这些依赖。其他环境先检查依赖，缺失时按当前工程约定准备，不假定全局安装了 sharp。脚本仅做本地媒体处理，不调用付费模型，也不自动写入网站数据。

```bash
node "<加载技能返回的目录>/scripts/video-frames.mjs" "<原视频绝对路径>" "<输出目录>" '[0.6,2.5,4.4,5.3,6.1,6.8]'
```

采样秒数根据分析需要从原片实际区间确定，按时间升序；脚本支持1–160个非负秒数，不自动检测切镜。它选择不早于采样点的真实帧，临近切点/片尾需留出至少一帧余量，结果以实际 `time` 为准。网站抽帧以实际工具返回的帧和时间为准。

输出单帧 `frames-*/frame-*.jpg`、拼图 `sheet-*.jpg` 和 `frames.json`。每张拼图最多12帧；命令行每三个采样点归为一组 `sample-N`，这只是本地采样组，不是网站镜头 ID。需要入库时，依据原片区间和真实项目 ID 建立关联。

读取拼图及其帧映射：`row/column` 从0开始，`label` 对应格内编号，`frameIndex` 是镜头内的帧索引，`time` 是实际原片秒数。网站 `breakdown` 返回的 `sheets[].frames` 提供逐格映射、各镜头 `frames` 提供可保存的单帧 ID 和时间；独立脚本使用 `frames.json` 中的 `sheets[].frames`。依据实际来源镜头 ID 和帧号保存证据，不把整张拼图当成一个镜头或单帧资产图。

拼图用于概览和关联；小字、人脸或关键道具看不清时，再读取相应单帧或加密局部采样，不猜测细节。当前 Agent 查看网站拼图、原片帧或资产图时，用 `builtin_read_image` 传任务返回的 `fileId`；工作区图片传 `path`，二者只选一个。`builtin_read_file` 默认读图片也会返回视觉内容。图片工具将像素作为模型图像输入返回；URL、文件名、发布成功或 Base64 文本均不能证明看过画面，不把 JPG 当 UTF-8 文本读取。按同页 `frames` 映射解读，再处理下一页，避免一次读取所有原图。读取失败先处理实际文件错误，不因读图失败重复提交付费任务。减少图片和重复转写可缩小输入，但 token、费用和响应速度按实际请求记录判断，不保证每次更快。

## 拉片记录

按网站当前 schema 保存字段；尚无来源字段时，以下作为分析草稿的信息要求，不是可以直接调用的 API schema：

| 内容 | 记录要求 |
| --- | --- |
| 来源 | 原视频 fileId 或用户提供的真实文件/URL，来源版本 |
| 镜头 | 稳定标识、原片开始/结束时间、参考帧 |
| 场次与主体 | 实际地点/内外/时间、出现的人物及关键道具，未知项标待确认 |
| 画面与动作 | 谁在何处做什么，动作对象、视线、入离画与重要反应 |
| 镜头语言 | 可见的景别、构图、机位变化、运镜、转场；判断不确定时明确说明 |
| 声音 | 原始对白、说话者/旁白、可听音效与环境声；不猜音乐名称 |
| 关系 | 真实资产 ID 或尚待应用草稿中的临时关联，避免同名混淆 |
| 待确认 | 时间切点、人物身份、对白、道具归属等具体问题和来源区间 |

时间满足 `0 <= start < end <= duration`；明确所分析区间，核对是否漏段。原片时间用于回看，目标顺序与目标时长另存。用户指定裁掉部分内容时保留裁切决定，不伪称完整覆盖原片。

不能从成片画面反推精确焦距、光圈、灯具型号、调色软件数值。描述可见效果即可，如暖色、低对比、浅景深。

## 去重与形态

- 人物：结合面部、服装、位置、动作连续性与对白判断。临时叫“人物 A”比猜名字可靠；确定新名字后仍保留 ID。
- 场景：地点及连续空间关系优先。角度变化或近景切换不创建新地点；真实环境/时间变化才考虑必要形态。
- 道具：关注推进动作或剧情的实体。根据形状、位置、持有者与连续动作匹配；同一物品在两个人之间传递仍是一个资产。
- 形态：换装、明显年龄变化或物品重大状态变化可使用现有 variants。普通表情、景别和朝向不独立建形态。

## 补漏与重新分析

先读取已有资产、镜头和人工修改，再检查指定区间。用户没有指定时，优先检查标记待确认的区间和明显覆盖缺口，不自动重复昂贵的全片分析。

补漏输出应让人看清：已复用主体、确有依据的漏项、关联修正、仍不能确认的项。应用时保留已有稳定 ID，不全删重建。

合并重复资产前检查目标图片/形态/片段引用，按现有业务能力迁移关联。无法安全迁移时保留记录并说明阻塞原因，不先删除资产。

用户手动补入的主体也应关联来源帧/时间；暂时无法定位时保持待确认。不能因为缺少证据就虚构来源时间。
